# СЧЁТЧИК — своя аналитика вместо Plausible

Считаем посещения сами и складываем в Google-таблицу. Внешних сервисов нет,
платить не за что, данные лежат там же, где вся остальная отчётность.

Пока не сделаны шаги ниже — **счётчик выключен и ничего не пишет**. Сайт при
этом работает как обычно, ошибок нет.

---

## Разовая настройка (примерно 15 минут)

### 1. Завести таблицу

Google Диск → «Создать» → «Google Таблицы». Назвать
**БумБастик · Счётчик**. Листы создадутся сами, ничего вручную заводить
не надо.

### 2. Вставить код

**Только из самой таблицы:** «Расширения» → «Apps Script». Стереть всё, что
там есть, и вставить содержимое файла
`.vitepress/analytics/apps-script-boom-stat.js` из этой папки. Сохранить
(значок дискеты).

**Если скрипт отдельный** (заведён на script.google.com, а не из таблицы) —
он её не видит и падает с `null`. Лечится так: «Настройки проекта» →
«Свойства скрипта» → добавить `SHEET_ID` = набор символов из адреса таблицы
между `/d/` и `/edit`. Отдельный скрипт работает так же, разница одна:
меню «БумБастик» в таблице не появляется, а функции `testHit` и
`rebuildDaily` запускаются из выпадающего списка в редакторе.

Часовых поясов в Google **два**, и поставить надо оба, иначе цифры разъедутся:

- в Apps Script: шестерёнка «Настройки проекта» → **(GMT+03:00) Москва»** —
  по нему скрипт считает, к какому дню отнести событие;
- в самой таблице: «Файл» → «Настройки» → **(GMT+03:00) Москва** — по нему
  таблица показывает время и считают формулы вроде `TODAY()`.

Таблица, сделанная из импортированного xlsx, приезжает с американским
поясом. 24.08 из-за этого событие 13:23 отображалось как 02:23.

Проверка: обновить вкладку с таблицей → в меню появится **БумБастик** →
«Проверить приём событий». Нажать. Должен появиться лист `hits` со строкой
`/тест`. Появился — код на месте.

### 3. Опубликовать

В Apps Script: «Начать развёртывание» → «Новое развёртывание» → шестерёнка
→ **Веб-приложение**.

- Выполнять от имени: **я**
- Кому доступен: **все**

Нажать «Развернуть», разрешить доступ. Google покажет адрес вида
`https://script.google.com/macros/s/…/exec` — **скопировать его**.

> «Кому доступен: все» — обязательно. Иначе браузер гостя не сможет
> отправить событие, и таблица останется пустой. Секретов в скрипте нет.

### 4. Отдать адрес сайту

GitHub → репозиторий `mihail-izumov/boombastic` → Settings → Secrets and
variables → Actions → **New repository secret** (там же, где лежит
`VITE_SUBSCRIBE_API`):

- Name: `VITE_STAT_API`
- Value: скопированный адрес `…/exec`

### 5. Пересобрать сайт

Адрес попадает в сайт только при сборке, поэтому одного добавления мало.
Либо опубликовать любую правку ярлыком **📤 Опубликовать**, либо, если
править нечего: GitHub → вкладка **Actions** → слева «Deploy VitePress site
to Pages» → кнопка **Run workflow**.

Проверка: открыть b00m.fun, зайти на страницу бонуса, потом посмотреть лист
`hits` в таблице — там должны появиться строки.

## Как пользоваться

### Что в таблице

Лист один — `hits`. Одна строка = одно действие гостя. Никаких сводов рядом
не держим: цифра должна быть одна, иначе неизбежен вопрос «а какая из двух
правильная».

Считать людей, а не клики, помогает колонка `visitor` — это номер браузера.
Один человек, открывший страницу трижды, даст три строки с одинаковым
`visitor`. В сводной таблице для этого есть «Количество уникальных».

### Выгрузка в boom-cmd-data

Открыть в браузере адрес веб-приложения — скачается `boom-stat.csv`. Положить
в `~/work-2026/boombastic/boom-cmd-data`.

| Что нужно | Что дописать к адресу |
|---|---|
| всё, что накопилось | ничего |
| только за период | `?from=2026-08-01&to=2026-08-31` |

## Воронка наклейки (Охта Молл)

| Шаг | Событие в таблице | Где считается |
|---|---|---|
| Отсканировал QR, страница открылась | `Бонус — открыл` | b00m.fun |
| Нажал «Забрать» | `Бонус — забрать` | b00m.fun |
| Зарегистрировался | — | **пока не видно** |

Приход именно с наклейки виден по колонке `source` = `sticker-ohta`.
Метка берётся из ссылки в QR:

```
https://b00m.fun/bonus500/ohtamall?from=sticker-ohta
```

Последний шаг воронки закрыт: `lk.b00m.fun` — отдельный сайт, счётчика там
нет. Это следующий этап. **До тех пор «нажал кнопку» — это не
«зарегистрировался», и делить одно на другое нельзя.**

## Как добавить счётчик на новую кнопку

Два действия, оба обязательны:

1. В коде кнопки вызвать `track('Название события', { park: 'ohta' })`.
2. Вписать **ровно то же название** в список `EVENTS` в файле
   `.vitepress/analytics/apps-script-boom-stat.js` и обновить код в
   Apps Script.

Пропустить второй шаг — событие будет отправляться и молча выбрасываться.
Так сделано нарочно: адрес таблицы публичный, и без белого списка в неё
напишет кто угодно.

## Что счётчик не собирает

Ни имён, ни телефонов, ни почты, ни IP-адресов — их у сайта просто нет.
В таблицу попадает случайный номер, который живёт в браузере гостя и ни с
каким человеком не связан.

## Если цифр нет

| Симптом | Причина |
|---|---|
| Лист `hits` пуст после публикации | не задана переменная `VITE_STAT_API` или сайт не пересобрался после её добавления |
| «Проверить приём событий» работает, а с сайта пусто | развёртывание не «доступно всем» |
| Событие не появляется, остальные идут | название не вписано в `EVENTS` |
| Часть переходов в ЛК теряется | нормально: гость успевает закрыть вкладку. Расхождение до нескольких процентов — не поломка |
