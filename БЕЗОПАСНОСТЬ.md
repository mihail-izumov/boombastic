# Безопасность проекта

Короткая памятка: что можно публиковать в репозитории, а что нельзя.
Проверено 24.08.2026.

---

## Главное правило

Репозиторий `mihail-izumov/boombastic` — публичный. **Всё, что вы туда отправляете, видно любому человеку в интернете.** Включая историю: если секрет попал в коммит и вы удалили его следующим коммитом, он всё равно остаётся в истории и доступен.

---

## Что НЕЛЬЗЯ класть в файлы проекта

- Пароли, токены, API-ключи
- Приватные ключи (`id_rsa`, `.pem`, содержимое с `BEGIN PRIVATE KEY`)
- Файлы `.env` с реальными значениями
- Персональные данные клиентов, сотрудников, детей (ФИО, телефоны, адреса, фото)
- Внутренние документы: договоры, финансы, зарплаты

Если такое нужно в проекте — оно идёт в **GitHub Secrets**, а не в код.

---

## Как правильно хранить секреты

В проекте это уже настроено верно на примере `VITE_SUBSCRIBE_API`:

1. Значение лежит в GitHub Secrets
   (Настройки репозитория → Secrets and variables → Actions)
2. Workflow `.github/workflows/deploy.yml` подставляет его при сборке
3. В коде есть только имя переменной, не значение

Локально для разработки создайте файл `.env.local` — он в `.gitignore` и на GitHub не попадёт.

---

## ⚠️ Важно про переменные `VITE_*`

Всё, что начинается с `VITE_`, **вшивается в собранный JavaScript и видно любому** в исходниках сайта b00m.fun. Даже если значение хранится в GitHub Secrets — оно секретно только в репозитории, но не на самом сайте.

**Можно** класть в `VITE_*`: адреса публичных эндпоинтов, идентификаторы аналитики, публичные ключи.

**Нельзя**: приватные ключи API, пароли, токены с правами на запись.

Если сервису нужен секретный ключ — он не должен вызываться из браузера. Такой вызов делается на стороне сервера.

## Мелочь, о которой стоит знать

В `ШПАРГАЛКА.md` указан путь `~/work-2026/boombastic/boom-fun` — то есть структура папок на рабочем компьютере видна публично. Практического риска нет, но это пример того, как безобидные на вид файлы раскрывают детали. Проверяйте, что попадает в коммит.

---

## Если секрет всё-таки утёк

1. **Сразу отзовите или смените ключ** в том сервисе, которому он принадлежит. Это главное — удаление из репозитория само по себе не помогает.
2. Только потом чистите историю (`git filter-repo` или BFG Repo-Cleaner).
3. Считайте, что ключ скомпрометирован навсегда: публичные репозитории сканируются ботами в течение минут.

## Перед публикацией

Ярлык `📤 Опубликовать.command` показывает список файлов и объём правок и ждёт подтверждения. Не нажимайте `д` не глядя — если в списке файл, который вы не ожидали увидеть, нажмите `п` и посмотрите правки в GitHub Desktop.

Быстрая проверка проекта на секреты — в Терминале из папки проекта:

```
grep -rniE "token|secret|password|api[_-]?key|ghp_" \
  --include="*.md" --include="*.mts" --include="*.js" --include="*.vue" \
  --exclude-dir=node_modules .
```

Пустой вывод — всё чисто.
