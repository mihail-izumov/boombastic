## Аналитика

Plausible убран 24.08.2026. Считаем сами: `.vitepress/analytics/boom-stat.js`
(клиент) шлёт события в Google-таблицу, код таблицы — рядом в
`apps-script-boom-stat.js`. Подключение — в `theme/index.ts`.

## Стек

VitePress 1.6.3 · Vue 3 · чистый CSS (без Tailwind, без препроцессоров) · npm

```
npm run docs:dev      # локальный сайт, http://localhost:5173
npm run docs:build    # сборка (обязательно прогнать перед публикацией)
npm run docs:preview  # посмотреть собранное
```

**Деплой:** любой push в `main` → GitHub Actions → GitHub Pages → b00m.fun.
Домен из `public/CNAME`. Упавшая сборка = сайт остаётся старым.

**Секрет сборки:** `VITE_SUBSCRIBE_API` (GitHub Secrets) — только для `turbo/TurboSubscribe.vue`. Локально его нет, поэтому форма подписки локально не отправляет — это нормально, не «чинить».

**Секрет сборки:** `VITE_STAT_API` (GitHub Secrets) — адрес Apps Script счётчика. Локально его нет → счётчик выключен, это нормально. Настройка — в `СЧЁТЧИК.md`. Секрет должен быть **и** в GitHub, **и** в блоке `env:` в `.github/workflows/deploy.yml` — иначе в сборку не попадёт.

## Как устроены страницы

Все `.md` — **тонкие обёртки над Vue-компонентами**. Реального текста в markdown почти нет: frontmatter плюс один тег.

| Страница | Компонент | Примечание |
|---|---|---|
| `index.md` | `HomePage.vue` | `layout: home` + `boomHome: true`; подключается через слот в `Layout.vue` |
| `parks.md` | `ParksPage.vue` | + инлайн `<style>` и класс на `<body>` |
| `prizes.md` | `PrizotekaOnboarding.vue` | выбор парка |
| `prizes/piterland.md` | `PrizesPage.vue` | импорт вручную + data loader |
| `prizes/ohtamall.md` | `PrizesPage.vue` | то же |
| `charge.md` | `ChargeCardPage.vue` | |
| `rewards.md` | `BoomRewards.vue` | |
| `terms.md` | `TermsHub.vue` | все юр. документы внутри, отдельных URL нет |
| `turbo/index.md` | `TurboSubscribe.vue` | |
| `bonus500/ohtamall.md` | `Bonus500Page.vue` | тексты в `data/bonus500.js`, адрес зашит в QR наклеек |

**Два способа подключения компонентов** (оба используются):

1. Глобальная регистрация в `.vitepress/theme/index.ts` → пишешь тег прямо в `.md`
2. Локальный импорт в `<script setup>` внутри `.md` → так сделаны страницы Призотеки, потому что им нужны данные

`PrizesPage` глобально **не** зарегистрирован. `SignalT9Configurator` тоже — открывается из `SignalModalButton`.

## Данные

### Парки — `.vitepress/data/parks.js`

Используется **только модалкой «Войти»**. Формат:

```js
{ id, name, address, accent: '#HEX', lk: { status: 'active'|'soon'|'none', url } }
```

Файл подробно закомментирован по-русски, там есть готовая инструкция «как добавить парк». Экспортирует `lkParks` (фильтр `status !== 'none'`) и `PARK_STORAGE_KEY`.

### Призотека — JSON + data loaders

```
prizes/<park>.data.js              → загружает JSON при сборке
.vitepress/prizes/<park>/prizes.json       призы (Охта 475, Питерлэнд 344)
.vitepress/prizes/<park>/collections.json  { "<collection_id>": ["OM-0245", ...] }
.vitepress/prizes/<park>/settings.json     park_id, hit_threshold, queue_form_url, lk_url
.vitepress/prizes/shared/categories.json   [{ id, label, has_filter, icon_name }]
.vitepress/prizes/shared/collections-registry.json  [{ id, name, color, icon_name, order }]
```

Формат приза: `id` («OM-0001»), `name`, `status` (`available`/`was`/`soon`), `category`, `tickets`, `is_jackpot`, `collection`, `monthly_sold`, `emoji`, `queue`.

Данные уходят в `PrizesPage.vue` как props (все `required: true`) и раздаются детям через `provide/inject` — ключи в `.vitepress/components/prizes/prizoteka.js`.

⚠️ **`queue_form_url` в `settings.json` хранится в base64.** Это обфускация, не шифрование. Обычный URL туда вставлять нельзя — сначала закодировать.

## Дубли: где ломается больше всего

Одни и те же сведения лежат в нескольких местах и **должны совпадать**. Это главный источник ошибок в проекте.

**Список парков — три независимых места:**

1. `.vitepress/data/parks.js` — модалка «Войти»
2. Захардкоженный массив внутри `ParksPage.vue` — страница «Парки»
3. Инлайн-скрипт в `config.mts` — ссылки в модалке «Игровой режим»

Плюс карточки на главной захардкожены в `ParksCards.vue`. **Добавление парка = правка минимум в трёх-четырёх местах.** Всегда проверяй все.

**Цвет парка** дублируется в `data/parks.js` (`accent`) и в `ParksPage.vue`.

**Названия папок Питерлэнда расходятся:** страница и data-файл — `piterland`, папка данных — `piterlend` (через «e»). Связь задаётся константой `PARK` внутри `piterland.data.js`. При копировании парка легко ошибиться.

**CSS-переменные объявлены дважды под разными именами:**

- `theme/style.css` — `--accent-lime`, `--neon-cyan`, `--text-primary`, `--font-heading: Montserrat`
- `theme/boom-styles.css` — `--lime`, `--cyan`, `--text-pri`, `--font-head: Inter` (!)

Перед добавлением стилей проверь, какая система используется в этом компоненте.

## Подводные камни

1. **`cleanUrls: true`** — внутренние ссылки без `.html`: `/charge`, `/prizes/ohtamall`. Ссылка с `.html` сломается.
2. **Тёмная тема принудительная** — `appearance: false` плюс `classList.add('dark')` в head-скрипте. Светлых вариантов переменных нет, стили пиши только под тёмную.
3. **Инлайн-скрипт в `config.mts` (~200 строк ванильного JS) — самое хрупкое место проекта.** Там живут: модалка «Игровой режим», перехват кликов по `.VPSocialLink`, доперевод интерфейса VitePress **сравнением текста**, трекинг событий (`track()` → `window.boomTrack`). Ломается тихо, ошибки сборки не даёт. Обновление VitePress может сломать перевод. Правь осторожно и предупреждай владельца.
4. **`socialLinks` в конфиге — не соцсети.** Два пункта с `icon: 'github', link: '#'` и `ariaLabel: 'gamemode-link'` / `'apply-link'` — это хуки для кнопок «Игровой режим» и «Войти». Не удалять как мусор.
5. **Битый JSON Призотеки роняет сборку целиком** — все props `required`. Опечатка в `id` категории или коллекции ошибки не даст, но приз молча выпадет из фильтров.
6. **Data loaders работают только при сборке и старте dev-сервера.** Правки JSON подхватываются на лету, но новый парк требует создать `prizes/<name>.md` + `prizes/<name>.data.js` + папку `.vitepress/prizes/<park>/` с тремя JSON.
7. **Хардкод абсолютного домена:** `https://b00m.fun/shark-eyes-icon-electric.svg` в `Layout.vue` (прелоадер, дважды) и `BoomRewards.vue` — локально грузится с прода.
8. **Инлайн-`<style>` с `!important` в `parks.md` и `prizes.md`** ломает вёрстку VitePress намеренно. `parks.md` вешает класс на `<body>` в `onMounted`/`onUnmounted` — при копировании страницы класс может залипнуть.

## Соглашения

- **Язык:** интерфейс, контент и комментарии в коде — русские. Комментарии подробные, пиши так же.
- **Имена файлов:** латиница. Компоненты `PascalCase.vue`, данные `lowercase.js`, JSON `lowercase.json`, страницы короткие однословные (`parks.md`, `charge.md`).
- **Исключение:** служебные файлы для владельца в корне — кириллица и эмодзи (`ШПАРГАЛКА.md`, `.command`-ярлыки). Это намеренно.
- **Папка `Parks/`** (с большой буквы, не путать со страницей `parks.md`): `Parks/<Город>/<улица_дом>/progress/<ДД-ММ-ГГГГ>.md`
- **Картинки:** `public/` = корень сайта, файл `public/foo.svg` доступен как `/foo.svg`. Фото парков: `public/parks/<город-3буквы>/<улица-сокр>/<ДД-ММ-ГГГГ>/prkx-<город>-<ДД-ММ-ГГГГ>_<номер>.jpeg`
- **Новые служебные `.md` в корне** добавляй в `srcExclude` в `config.mts`, иначе станут страницами сайта.

## Чек-лист перед публикацией

1. `npm run docs:build` проходит без ошибок
2. Если добавлял парк — проверены **все** места из раздела «Дубли»
3. Если правил Призотеку — `id` категорий и коллекций существуют, `icon_name` есть в `PrizeIcons.vue`
4. Внутренние ссылки без `.html`
5. Новые `.md` в корне добавлены в `srcExclude`
6. В коммит не попало ничего лишнего — ярлык публикации показывает список, но проверить стоит
